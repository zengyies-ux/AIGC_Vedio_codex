# 核心学习包维护

此目录维护干净核心学习包的白名单、专用说明和手动构建脚本。它不会自动同步或定时打包；只有用户明确要求发布新版本时才运行。

## 当前发布流程

1. 先完成本次规则修改及受影响范围的必要检查。
2. 更新`package_config.json`中的版本、发布日期和变更摘要。
3. 更新`CHANGELOG.md`。
4. 手动运行：`python3 packaging/build_core_package.py`
5. 从脚本输出确认文件数、断链、绝对路径和SHA-256。

发行文件写入根目录`releases/`。历史项目、资产、审片、旧Skill和团队SOP不在白名单内，不能因为新增文件而自动进入压缩包。

1.2.0沿用显式白名单，新增匿名`validation/director_v32.md`；本机剧本、素材、词表、模型、缓存、聊天及含私有路径的实施文件／启动词仍排除。构建生成的空白项目索引只在包内，不覆盖活动项目索引。

本轮发布V3.2试制版，配置、文件名、SHA与标签必须一致；GitHub Release设为prerelease。检查规则／工具和当前包即可发布，实际新窗口与成片待用户验证；不能把发布或文档验收当常规模式启用依据。公开提交逐项暂存，只包含核查过的核心、启动词、匿名说明、发行配置与产物；保留旧包、旧标签及main。
