# 核心学习包维护

此目录维护干净核心学习包的白名单、专用说明和手动构建脚本。它不会自动同步或定时打包；只在用户授权候选开发或发布新版本时手动运行。

## 当前发布流程

1. 先完成本次规则修改及受影响范围的必要检查。
2. 更新`package_config.json`中的版本、日期、变更摘要和实际状态。`release`写`releases/latest.json`；`local_candidate`或`branch_candidate`写`releases/candidate.json`，保持正式推荐元数据及旧附件。
3. 更新`CHANGELOG.md`。
4. 手动运行：`python3 packaging/build_core_package.py`
5. 从脚本输出确认文件数、断链、绝对路径和SHA-256。

发行文件写入根目录`releases/`。历史项目、资产、审片、旧Skill和团队SOP不在白名单内，不能因为新增文件而自动进入压缩包。

1.7.0使用全新候选文件名，保留1.6.x及所有旧发行物。白名单纳入唯一DEPLOYMENT、Windows CPU后端／平台锁／环境自检及必要行为测试、轻量网页回执日志／完整执行链与匿名V3.7说明；不收真实项目、页面／账户／ID、素材／截图／媒体／模型／缓存。包内README仅导航，清洁项目索引只在ZIP生成，不覆盖本地索引。

历史1.7.0阶段曾把候选写入latest.json；从1.8.0起采用上述分流，旧做法不再作为当前构建指令。构建文件不证明已经推送、发布或现场验收；远端状态和附件须另核。
