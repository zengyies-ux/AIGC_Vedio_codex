# 核心学习包维护

此目录维护干净核心学习包的白名单、专用说明和手动构建脚本。它不会自动同步或定时打包；只有用户明确要求发布新版本时才运行。

## 当前发布流程

1. 先完成本次规则修改及受影响范围的必要检查。
2. 更新`package_config.json`中的版本、发布日期和变更摘要。
3. 更新`CHANGELOG.md`。
4. 手动运行：`python3 packaging/build_core_package.py`
5. 从脚本输出确认文件数、断链、绝对路径和SHA-256。

发行文件写入根目录`releases/`。历史项目、资产、审片、旧Skill和团队SOP不在白名单内，不能因为新增文件而自动进入压缩包。

1.6.1使用全新候选文件名，保留1.6.0及旧发行物；显式白名单新增根DEPLOYMENT.md，包内README只作地图并链接该唯一部署说明。规则、唯一扩展、通用启动基线与匿名验收按需同步，不收真实剧本、网址、资源ID、媒体、截图、账户、会话或缓存。清洁项目索引只在ZIP生成，不覆盖本地活动索引。

本轮获准将核心、部署说明及候选推送codex/director-v3-6工作分支，release_status为branch_candidate，不创建本版tag／Release，不改main或旧标签。latest.json仅是候选构建信息；远端分支推送须单独核提交和附件哈希，不能当稳定发布。后续如获正式发布授权，再核版本占用并执行新的发布回读，不覆盖旧包。
