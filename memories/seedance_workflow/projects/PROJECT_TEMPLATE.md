# 新项目模板

## 推荐目录

```text
project_slug/
├── project_overview.md
├── production_state.md
├── assets/README.md
├── source/
├── prompts/
│   ├── INDEX.md
│   └── ep01_segment01_v1.md
└── reviews/
```

小项目采用上面的扁平分集命名，既有项目不为套模板迁移文件。记录较多时再增加`production_history.md`，将历史过程移入并明确标注；它不是每次任务必读入口。

## `project_overview.md`

只记录长期不变的项目事实：

```text
# 项目名

## 类型与目标市场
- 画幅：
- 语言：
- 主要模型：
- 叙事类型：海外旁白短剧 / 真人大量对白剧 / 其他
- 节奏基线：海外旁白短剧最低真实镜头数按总时长除以3后向上取整，每个编号镜头原则上不超过3秒；若另有项目偏好在此记录

## 当前故事目标
- 观众代入点：
- 核心关系：
- 视觉基调：

## 场景资产规划
- 连续多集的大地点先按实际动作功能区拆分，例如入口、核心装置区、关键道具区、观众区；一张简单资产承担一个明确空间职责，不用一张复杂全景覆盖所有机位。
- 只有会反复入镜并影响连续性的不可逆变化才建立状态变体，例如蛋糕完好／倒地、门关闭／敞开；普通反打不重复造图。
- 区域名｜关键固定物｜承担的剧情动作｜需要支持的机位｜现有资产／待补资产：

## 主要角色
- 角色名：身份、外观参考、不可改变事实与核心关系；不把角色统一写成固定表情

## 固定制作偏好
- 用户在本项目明确确认的偏好
```

## `production_state.md`

只记录当前执行状态：

```text
# 制作状态

## 当前进度
- 制作状态：
- 审核状态：
- 当前待办与待确认范围：
- 依据：用户反馈 / 实际成片检查 / 仅文本设计
- 当前模型：

## 当前素材与版本入口
- 素材状态：assets/README.md
- 当前文本及实际采用情况：prompts/INDEX.md
- 图片编号在每次生成内独立分配，不设全项目固定编号

## 整集分段与情绪归属
- 三段/四段候选与采用理由：
- 每段全局区间、主情绪命题与主要承载者：
- 必须兑现的直接回应、关系人余波与群众职责：
- 主要复杂执行核心与失败后的返抽范围：
- 每个生成边界的对白、动作及状态稳定性：

## 场景空间基线
- 本集实际使用的功能区及对应场景资产：
- 固定物：
- 入口与路线：
- 人物站位与摄影机侧：
- 关键光源：

## 连续状态
- 角色：
- 道具：
- 世界条件：
- 实际源视频与末尾状态（截图仅供内部审片）：
- 下一段开场空间、时间与接触关系：
- 本段移动目的、路线、跟随/避让与新落点：
- 计划方式及源片依赖：独立生成 / 视频延长
- 用户确认的实际方式：未确认时不以计划代填

## 下一段内部接力
- 当前认知与情绪落点：谁已知道/误信什么、关系刚发生什么变化，下一段不能退回旧心理状态
- 当前段已兑现的高点与留下的期待；下一段拟延续的表演/视觉落点，只记判断结果
- 只供Codex读取，不复制进当前提示词；既有栏目承载，不另建导演方案文件
```

制作状态只维护当前事实、待办与必要连续性。若文件开始出现多轮“前次／最新／上一阶段”，立即把被覆盖内容移入`production_history.md`，而不是继续在顶部叠加新状态。项目完成后将本页改为简短归档状态，明确“当前无活动任务”，并同步更新总索引。项目概览和总索引只链接状态页，避免重复维护进度。

## 素材与版本索引

- `assets/README.md`：按语义名称记录用途与状态，区分已展示、用户确认已备、待补、停用和临时路径；未核验的文件可用性不写成已确认。
- `prompts/INDEX.md`：开头只列当前可执行文本与实际采用依据或未确认项；区分镜头修订、仅格式修订及旧合辑，最新文本不自动等于已生成版本。被覆盖的“当前入口”和长篇版本过程移入`prompts/HISTORY.md`；每次修稿只补受影响项，完成反馈覆盖历史待生成描述。
- 历史提示词不覆盖。归档文件顶部标明历史属性和当前入口，不让当时的“当前”“下一步”冒充最新事实。

## 复盘文件

只有拿到真实成片或明确用户反馈时建立：

```text
预期 → 实际 → 成立部分 → 偏差 → 原因假设 → 最小修正 → 验证结果 → 规则状态
```

项目结论默认留在项目内。跨项目重复验证后，才升级到核心知识库。
